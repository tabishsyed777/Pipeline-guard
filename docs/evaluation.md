# Initial evaluation

Run `python -m unittest discover -s tests -v` and `python -m pipelineguard.demo` from the source checkout.

The initial local run used Python 3.12. All 18 tests passed (16 unit/component checks and two subprocess CLI integration tests). The demo detected the schema alias change and missing quantity, produced a valid separate repaired CSV, passed all six independently authored replay cases, and accepted the healthy control with zero findings. No model was called. An editable installation succeeded and the installed `pipelineguard` command accepted the healthy CSV. All four generated HTML reports were opened in Chromium with visible finding tables and zero page errors.

Tests also cover contract binding, unapproved repairs, rename collisions, malformed CSV widths, non-finite numbers, fractional integers, division by zero, chained transform blocking, empty data, reserved output names, HTML escaping, source preservation, and rejection of intentionally incorrect expected answers. The CLI integration test checks the actual exported CSV and verifies that a failed repair does not write one.

The plan is selected from the broken input and declared contract before the verifier reads expected outputs. Expected outputs are handwritten fixture labels, not generated by executing the transformation under test. The fixtures are public and small; this is a reproducibility check, not a security boundary, agent benchmark, or general accuracy estimate.

The subprocess integration tests execute inspection, repair, verification, and a healthy control through the real module entry point. They also assert rejection of an existing output directory, invalid data, and a tampered contract fingerprint without exporting an invalid CSV.
